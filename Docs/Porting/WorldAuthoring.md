# World prefab authoring

The first GameObject scene uses the same 1280×720 source projection. `WorldProjection.WorldToScene` maps logical arena coordinates to a 100-pixel-per-unit orthographic camera; sprites are imported at 100 PPU. Actor prefab roots sit at their logical feet. `SortingGroup.sortingOrder` follows projected foot depth, so sprites overlap in the source order.

`Survival Legend > Build World Prefabs` runs `WorldPrefabBuilder.EnsureAssets()`. It slices the committed player atlases into 8 directions × 6 frames, bakes 8 directions × 4 frames of the original SD enemy procedure into persistent PNG atlases, and creates `DirectionalSpriteSet` assets. Frames are 128×128, point filtered, no mip maps, with pivot `(0.5, 0.125)`; actor display scales are `.55` for heroes and `.58` for enemies. The base actor prefab has `Shadow`, `Shield`, `Body`, `HealthBackground`, `HealthFill`, and `NameLabel` children. Saved player and enemy prefab variants use those same editable parts. The Korean label font is the bundled Noto Sans KR Bold asset.

`WorldVisualDatabase` maps content IDs to sprite sets and prefab variants. New `CharacterDefinition` or `EnemyDefinition` IDs need one new visual database entry; missing IDs fall back to the first saved character or enemy definition so added content stays playable. Variants and database entries can be edited in the Inspector. Existing prefabs are preserved when the builder runs again.

`ArenaMap` is a saved prefab with the original floor and checker stones baked into one `Backdrop` sprite. The center ritual rings and four corner lamps are separate, editable SpriteRenderer objects under `Decorations`. The `Ground`, `FloorTiles`, `Decorations`, `Bounds`, and `SpawnMarkers` layers can hold further authored objects. Individual checker stones are part of the backdrop image; edit that texture or add tile overlays under `FloorTiles` to change them. The arena's gameplay width, height, and inset come from `GameDatabase`; the map prefab does not duplicate them. Adding enabled `ArenaSpawnMarker` components under `SpawnMarkers` passes their logical positions to the next run snapshot. With no markers, source edge spawning remains intact. Select the map to see the current gameplay bounds as a gizmo.

The backdrop sorts at `-10000`, zones at `-4000`, actors by projected foot depth, projectiles at `9000`, effects at `10000`, and aim/order markers at `11000`. Set decorative SpriteRenderers below `-4000` for floor details; use a suitable depth relative to actors for raised objects. The `Bounds` child is an editing layer, while collision and spawn limits remain in the database snapshot.

`WorldPrefabBuilder.ConfigureScene(worldRoot, game, camera)` places the ArenaMap prefab instance, child pool layers, and a `WorldPresenter` on the world root, and binds `game.ArenaMap`. `WorldPresenter` checks `SurvivorGame.Generation`, reconciles actor/projectile/zone/effect IDs, and returns inactive views to pools at reset or expiry. It uses simulation `Time`, `Life`, and animation state, so pause, card selection, and resume preserve the visible world state. `AimMarkerView` derives its range and radius from the selected skill's patched targeting data. The completed Canvas UI lives under the scene's UI root and uses saved UI prefabs.

Review checkpoints: inspect each atlas in the Sprite Editor for foot pivot and complete weapon bounds; move a hero through all eight facings in Play Mode; verify enemy/hero depth crossing, projectile elevation and effect expiry; edit a decoration and a spawn marker in the saved map prefab; start a second run and confirm no old effects remain.
